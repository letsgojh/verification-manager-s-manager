# 07-cycle-integration

## 목적

`00`~`06`을 순서대로 한 번에 실행해서 전체 파이프라인이 로컬에서 끊기지 않고 도는지
확인한다. 각 phase의 출력 스키마가 다음 phase의 입력 스키마와 맞아 수동으로 값을 고치지
않아도 이어지는지가 핵심 (내용 품질이 아니라 **연결이 안 끊기는지**를 본다).

## 실행법

```bash
./phases/07-cycle-integration/run_all_local.sh
```

venv가 있으면 스크립트가 알아서 `source venv/bin/activate` 한다. `GEMINI_API_KEY`는
`.env`에 있어야 한다(03, 04에서 실제 Gemini 호출).

## 순서

```
00(샘플 오디오 존재 확인)
  → 02(전사, --model tiny)
  → 03(의미 판단, source=meeting)
  → 04(문서 초안)
  → 05(승인, --mock으로 대체 — 실제 Discord DM 대기 없이 무조건 "수락")
  → decision == approved일 때만 06(Notion 반영, --dry-run)
```

각 단계 사이 변환(예: segments를 하나의 text로 합치기, 이전 phase 출력을 다음 phase 입력
스키마로 감싸기)은 스크립트 안에서 작은 인라인 파이썬으로 처리한다.

## 05를 --mock으로 대체하는 이유

실제 Discord DM 승인은 사람이 버튼을 눌러야 진행되므로 자동화된 로컬 통합 스크립트에는
맞지 않는다. 실제 DM 승인 흐름 자체는 `phases/05-pm-approval/README.md`에서 별도로
검증했다. 여기서는 04의 실제 출력을 05(mock)의 `--input`으로 넘겨 스키마 호환성만 확인한다.

## 검증 결과 / 알아둘 점

- 실행 결과: 에러 없이 끝까지 완주 (exit code 0)
- `sample_meeting.wav`가 실제 회의가 아니라 뉴스/잡담 텍스트를 이어붙인 합성 샘플이라,
  03은 `is_meaningful: false`로 정확히 판단했다. 04는 (이 로컬 스크립트에서는) 판단 결과와
  무관하게 조건 없이 계속 실행되도록 되어 있어서, 관련 없는 문장 하나를 골라 문서 초안을
  만들었다 — **파이프라인 연결이 끊기지 않는지 확인**이 목적이라 문제는 아니지만, 실제
  운영에서는 `chat-poll.yml`처럼 "의미 있을 때만 04 실행"하는 조건이 필요하다(Phase 08에서
  다룸).

## 통과 기준

스크립트가 에러 없이 끝까지 실행되고, 각 단계의 출력이 다음 단계 입력 스키마와 맞아
수동으로 값을 고치지 않아도 이어진다.
